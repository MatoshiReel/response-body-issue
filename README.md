## response-body-issue: Python library of standardized HTTP response bodies.
***
[![license](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

Read in another language: [ru](./localization/ru/README.md)

## Description
***

The response-body-issue Python library contains DTO classes 
for HTTP 4xx responses. The library provides a unified response-body format
for microservice-based server architectures. 
It allows services to expose a consistent error contract
without exposing internal implementation details, such as 
service classes, exceptions, internal architecture, or underlying frameworks.

## Getting Started
***

To build the project, run the following commands from the project’s root directory:

1. Create a virtual environment:
```bash
python -m venv .venv
```
2. Activate the virtual environment:

* Linux and macOS:
```bash
source .venv/bin/activate
```
* Windows (cmd):
```bash
.venv\Scripts\activate
```
3. Check that `pip` is working in the virtual environment:
```bash
python -m pip --version
```
4. Build the project:
```bash
python -m pip install build && python -m build
```
The .whl file of the library will be generated in the project’s /dist directory.

To install response-body-issue as a dependency in another project, 
create a /dist directory in the root directory of the project that will use the library. 
Copy the generated .whl file into the /dist directory 
and run the following command from the project’s root directory:
```bash
pip install ./dist/response_body_issue-0.1.0-py3-none-any.whl
```

## Usage
***

1. Simple example of creating a `RequestError` entity without message parameters:
```python
from resbo.error import RequestError
from resbo.reason import ErrorReason

RequestError(errorReason=ErrorReason.JSON_FORMAT.name).system_message()
```

The resulting object in JSON format:

```json
{
  "errorReason" : "JSON_FORMAT",
  "message" : "Invalid JSON format."
}
```

2. Example of creating a `RequestError` entity 
with one parameter for the standardized message generated by `ErrorMessageFactory`:
```python
from resbo.error import RequestError
from resbo.reason import ErrorReason

RequestError(errorReason=ErrorReason.EMPTY.name).system_message("field_name") # {} is empty or null.
```

The resulting JSON object:

```json
{
  "errorReason" : "EMPTY",
  "message" : "field_name is empty or null."
}
```

3. Example of creating a `RequestFieldError` entity
   with a few parameters for the standardized message generated by `ErrorMessageFactory`:
```python
from resbo.error import RequestFieldError
from resbo.reason import ErrorReason

RequestFieldError(errorReason=ErrorReason.LESS_SIZE.name, field="password").system_message("password", "6") # {} cannot be less than {}.
```

The resulting JSON object:

```json
{
  "field" : "password",
  "errorReason" : "LESS_SIZE",
  "message" : "password cannot be less than 6."
}
```

4. Example of creating a `RequestFieldError` entity
   with a custom message:
```python
from resbo.error import RequestFieldError
from resbo.reason import ErrorReason

RequestFieldError(errorReason=ErrorReason.LESS_SIZE.name, field="password").custom_message("Password cannot be less than 6 characters!")
```

The resulting JSON object:

```json
{
  "field" : "password",
  "errorReason" : "LESS_SIZE",
  "message" : "Password cannot be less than 6 characters!"
}
```

To determine the number of parameters required for a standardized message,
refer to the docstring documentation for the `ErrorMessageFactory` class.

## Internal Structure
***

- **Issue** - contains the base Issue DTO.
- **Error** - contains DTOs for 4xx responses.
- **Reason** - contains the enum defining 4xx response reasons.
- **Message** - contains the factory for standardized error messages.
